# 开源项目 README 规范标准

为开源项目打造统一、克制、清晰且可复现的首页门面，兼顾「30 秒看懂价值」与「60 秒上手运行」。

先读仓库实际代码、配置文件与 `LICENSE` 再动笔，不编造尚未实现的命令、环境变量、CI 或演示链接。按需查阅：

- 四大项目类型模板：[参考模板库](references/templates.md)
- 徽标参数与公式：[Shields 徽标规范](references/badges.md)
- 所属 `chius-me` 仓库时读取：[Chius 个人预设](references/chius-profile.md)

## 1. 核心原则

- **30 秒法则**：首屏必须明确回答三件事——这是什么？解决什么痛点？怎么跑起来？
- **克制与信息密度**：避免大段空洞叙述，善用表格、列表与可直接复制的终端命令块；徽标控制在 4～6 个且均附带有效跳转。
- **视觉先验**：Web / GUI / CLI 视觉产出型项目，首屏应放置清晰的预览截图、GIF 或在线 Demo 链接；没有现成截图时标注占位或待补充，不虚构图片路径。
- **主语言选择**：
  - 面向国际用户的通用工具、CLI、Worker/服务：主文档 `README.md` 用地道美式英文，按需配 `README.zh.md`。
  - 面向中文社区或个人创作的项目：主文档 `README.md` 用中文，按需配 `README.en.md`。
  - 同一文件内保持语言纯正，不在纯英文模板标题里夹杂中文括号。存在多语版本时，右上角放置切换锚点。
- **真实可复现**：前置依赖（Node/Python/Go/Docker 版本等）和最小闭环启动命令必须与仓库实情一致；徽标只挂仓库里确实存在的 Workflow、Release 与许可证。

## 2. 标准骨架（Standard Anatomy）

根据项目性质可增删非核心章节，但推荐保持如下顺序：

1. **语言切换器**（多语仓库时右上角右对齐）
2. **居中 Hero 头部**：可选 Logo（56–64px）+ 标题 + 1–2 句痛点描述 + 4–6 个 `style=flat` 徽标 + 直达链接
3. **视觉预览**（Demo 截图 / Terminal GIF，居中展示）
4. **核心特性**（3–8 条，加粗短标题 + 一句实质说明）
5. **快速开始**（前置要求 + 可复制的最小运行 / 安装命令）
6. **使用指南 / 部署方式**（按项目形态选 CLI 参数、Docker Compose、Wrangler 等）
7. **配置说明**（环境变量或配置项表格）
8. **架构与设计**（可选，复杂项目用简明图示或模块说明）
9. **许可证与页脚**（`LICENSE` 链接与作者署名）

## 3. 项目归类速查

先确定项目类别，再从 [参考模板库](references/templates.md) 选择骨架并填充仓库真实内容：

| 类型 | 典型场景 | 核心侧重点 |
| --- | --- | --- |
| **A: Web / Edge 服务** | Web 应用、API、Cloudflare Workers | 在线演示、环境变量表、本地启动与部署命令 |
| **B: CLI / Docker / 服务** | 命令行工具、MCP、Bot、容器化服务 | 包管理器/二进制/Docker 安装、CLI 参数表与权限说明 |
| **C: 主题 / 文档 / 创作** | 博客主题、设计系统、文档合集 | 预览大图、设计理念、引入与本地预览步骤 |
| **D: 精选列表 (Awesome)** | 资源索引、工具导航 | 目录锚点、收录标准、结构化表格与贡献准则 |

## 4. 验收清单

交付前逐项核对：

1. **链接有效**：双语切换锚点、相对文件路径（截图、文档、`LICENSE`）与徽标跳转目标均真实存在；未配置 CI 或 Release 时不挂虚构徽章。
2. **首屏完整**：包含项目名称、清晰一句话定位、关键链接与适当数量的统一风格徽标。
3. **命令闭环**：快速开始的前置依赖、包管理器和启动命令均与项目文件（如 `package.json`、`pyproject.toml`、`Dockerfile`）一致，可直接复制运行。
4. **协议一致**：文档内声明的开源协议与仓库根目录 `LICENSE` 一致。
5. **排版洁净**：代码块均标注语言标识，无未替换占位符（如 `{repo}`、`{owner}`）。
