# 地理照片标注

照片是主角，标注帮助读者认出地点与形状。默认使用清晰的无衬线地名、少量细白线和留白，不把每个边缘都描满，也不把小地图当作必需装饰。

首次使用先看 [新葡京示例](example/grand-lisboa/preview.png)，理解文字与照片的相对尺度。它只提供视觉方向；名字、坐标与轮廓不可复制到其他照片。

## 1. 判断需要哪些标注

- 使用用户原照片；保持画幅、构图和色彩。旋转按 EXIF 处理，所有坐标以显示方向为准。复制原文件时保留真实扩展名，不把 PNG 改名为 JPG。
- 先识别主角、可用留白和地名。地点不明且会影响标注时询问；不确定的名字先核实。
- 通常一组地点标题、一处主体标注、零到两段描线就够了。中文、英文或双语随用户内容选择，不强制英文。次要译名用较小字级。
- 照片没有干净位置时，减少标注；不要靠缩成看不清的小字硬塞信息。

## 2. 排版与描线

**文字：** 地区名放在稳定的留白里，主体名靠近主角但不压住细节。长地名换行或换位置。字距适度，不用宽字距把短标签拉成装饰线。渲染器按真实字体测量，左／右对齐的坐标指相应边缘。

**引线：** 仅在文字与地物的关联不清楚时加。终点落在明确可见的主体边缘，走最短清楚路径，避开其他文字与无关物体。实线引线和点状轮廓分工，避免满图同一种虚线。

**轮廓：** 只挑能帮助理解形状的可见边缘：建筑侧翼、山脊或岸线。一段描线从边缘开始，到遮挡或辨识不清处结束；不要为了闭合轮廓跨过天空、缺口或树木。线离真实边缘约 1–3 个预览像素即可，不能变成悬浮的第二个轮廓。

在原图上放大确定折点。边界清晰时可按局部颜色／梯度提取，再简化折线；自动提取结果要逐段复查，玻璃反光很容易被误判成天空。折点保留真实转折，平顺处减少点数。宁可少描一段，也不要用稀疏猜测点包围整个主体。

## 3. 按需添加地理元素

- **区位简图：** 只有用户需要区域关系、且有可靠边界数据时添加。标明覆盖的是城区、岛还是行政区，保留来源；不能把近似多边形当成真实边界。没有来源时省略。
- **拍摄点：** 只有可靠 GPS 或用户确认位置时标红点；在简图上用同一地理投影定位，不在照片空白处随意放点。照片中的建筑位置不是相机位置。
- **指北针：** 只用于能确定北向的俯视或地图式画面；普通地面仰拍不画。

这些元素的字段、坐标变换和比例约束见 [spec 参考](references/spec.md)，需要时再读。

## 4. 渲染与交付

文字和线条由本技能的排版脚本绘制，不需要图像生成或浏览器。用户额外要求改变照片本身时，先完成对应图像编辑，再做标注。

读取 [spec 参考](references/spec.md)，把原图和 `spec.json` 放在本次输出目录，然后运行：

```bash
python3 "<skill_dir>/scripts/render_plate.py" "<output_dir>/spec.json" \
  --preview "<output_dir>/preview.png" --strict
```

需要 Python 3 和 Pillow；缺依赖时可用 `uv run --with pillow python` 替代 `python3`。脚本会查找系统字体，找不到时用 `--font /path/to/font.ttf`；中文需要含中文字形的字体。

- 输出全尺寸 `plate.png` 和最长不超过原宽的 1080px 宽预览；原图不覆盖，输出保留色彩配置，不携带原图 GPS 元数据。
- `--strict` 拦截文字重叠与安全边距问题；它不能验证地名、描线贴合程度或文字与照片主体的遮挡。
- 先看预览确认标题能读、照片仍是主角，再放大核对轮廓、字形和引线端点。发现错误改 spec 并重渲染；不要把运行成功当成视觉验收。
- 技能示例与试做放在 `<skill_dir>/example/<slug>/`；普通用户作品放到用户指定目录，未指定时使用工作区的 `place-plates/<slug>/`。同一作品修改时保留旧版，避免覆盖原稿。
- 最后展示成片，附原尺寸文件链接，简述实际标注内容。目录只保留原图、spec、成品和有用的对比，不堆浏览器截图或临时裁图。
