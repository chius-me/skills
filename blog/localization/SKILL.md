# 博客校对与多语本地化

以简体中文原稿为唯一基准（Single Source of Truth），先修正原稿的排版、标点与技术名词，再分别按台湾资讯圈习惯（`zh-TW`）与英语母语技术博主语感（`en-US`）完成语意化重写。保留第一人称随笔的真诚、轻松与冷幽默，拒绝公文腔与逐字机翻。

详细术语对照表与正反例句见 [术语与译例参考](references/terminology-and-examples.md)，需要时再读。

## 1. 确定范围与工作流

- **先校对原稿，再做翻译。** 中文原稿存在标点混用、病句或术语错误时，先修正中文原稿，再以定稿后的中文为准同步其他语种，避免把原稿笔误带入译文。
- **保持结构与事实对齐。** 多语言版本（如 Hugo 的 `<slug>.md`、`*.zh-tw.md`、`*.en.md`）保持相同的 Front Matter 元数据（`date`、`draft`、`layout` 等）、段落层级、代码块与图片引用；不增删事实或虚构经历。
- **保留作者人设与语气。** 作者是兼具硬核折腾精神（Homelab、Linux、自托管、开发）与生活气息的个人博主。译文要像母语博主自己写的随笔，不要翻成生硬的企业说明书或教科书。

## 2. 简体中文原稿校对（`zh-CN`）

| 检查项 | 规范要求 |
| --- | --- |
| 标点符号 | 全文使用全角中文标点；省略号用六点 `……`（不用 `......`）；感叹号不加前置空格（用 `！！！` 不用 ` !!!`）；列表加粗前缀后用全角冒号 `**技术**：` |
| 内联空格 | `[链接](url)` 或 `**加粗**` 内部首尾为汉字或全角符号时，与紧邻汉字之间**不加空格**；内部首尾为英文或数字时，与紧邻汉字之间**保留一个半角空格**（紧邻全角标点除外） |
| 作品与标题 | 动画、影视、书籍、专辑名加书名号 `《》`（带链接写为 `[《作品名》](url)`）；Markdown 各级标题（`##`、`###`）下方空一行 |
| 专有名词 | 严格遵循官方大小写：`macOS`、`JetBrains`、`GitHub Actions`（复数）、`Argo CD`、`OpenCode`、`NetBird`、`Hugo`、`SumatraPDF`、`Last.fm`、`City Pop`、`GPT-5.4` |
| 单位与数字 | 容量数字与单位间留空格（`16 GB`、`3 TB`）；同篇内功率写法保持统一（中文可写 `200W`） |
| 易错用词 | 软硬件优化用“调校”（不用“调教”）；开篇用 `## 前言`（不用“首言”）；指代过去用“那时候／当时”（不用表将来的“届时”）；Control Plane 译为“控制平面”；PVE 中的 Guest 译为“VM 和容器／实例”（不用机翻味浓的“来宾”） |

## 3. 台湾正体本地化（`zh-TW`）

1. **绝不仅做字形直转。** 不能只跑一遍简转繁工具，必须将大陆惯用词转换为台湾资讯圈与日常习惯用语（如“博客→部落格”、“软件→軟體”、“内存→記憶體”、“电源→電源供應器”、“刷屏→洗版”、“考研→考研究所”，完整对照见 [参考文档](references/terminology-and-examples.md)）。
2. **统一正体标点与字形。** 引号一律改为直角引号 `「」` 与 `『』`，不留西文弯引号 `“”`；使用台湾标准正体字形（用 `什麼` 不用港式 `甚麼`，用 `裡`、`線`、`設定`、`網路`、`連結`、`專案`）。
3. **避免台版机翻词。** 虚拟化语境下的 Guest 译为 `VM`、`VM 和容器` 或 `執行個體`，不译为生硬的 `客體`；“考研”译为自然的 `考研究所`，不译为死板的 `研究所入學考試`。
4. **本地化外部链接。** 文中若包含带语言路径的外部链接（如 `nodejs.org/zh-cn/...`、`learn.microsoft.com/zh-cn/...`），同步改为 `zh-tw`。

## 4. 美式英语语意化重塑（`en-US`）

1. **重写语流，保留灵魂（Rewrite for Native Flow）。** 先理解中文句子的核心意思、情绪与槽点，再用自然的美式英语表达，允许合理调整语序与句式结构。
2. **还原幽默感与网络黑话。** 中文里的调侃与比喻要用对应的英文地道习语传达（例如硬盘“反复横跳”译为 *flapping* / *bouncing back and forth*，“在机箱里蹦迪”译为 *throwing a rave in the bay*，“刷 LeetCode”译为 *grinding LeetCode*）。
3. **补充跨文化上下文。** 对中国特有的概念补充简短的国际通用说明，避免英语读者费解：如 `天选 4` 写为 `ASUS TUF Gaming (Tianxuan 4)`，`211 院校` 写为 `a Project 211 university`，`2027 届` 写为 `Class of 2027`。
4. **拒绝中式英语技术词（Chinglish）。** “大模型”译为 `LLMs` 或 `foundation models`（禁用 *large models*）；“打洞”译为 `NAT traversal`；“软路由”译为 `OpenWrt router`；“光猫”译为 `ONT (fiber modem)`。
5. **遵守英文排版规范。** 作品名使用斜体 `*[Nichijou](url)*`（不用书名号）；破折号用紧贴两侧单词的 em dash `—`；撇号统一用直撇号 `'`；数字与所有单位间均留空格（`200 W`、`16 GB`、`3 TB`）；带语言路径的外部链接改为 `en` 或 `en-us`。

## 5. 验收与交付

- 逐文件检查换行符统一为 `LF (\n)`，文件末尾保留换行。
- 对照简体中文基准稿，核对繁中与英文是否遗漏分句、列表项、代码块或图片，确认无残留的简繁混杂、多余空格或错别字。
- 在 Hugo 等静态站点仓库中，修改后运行 `hugo --gc --minify` 验证构建通过，确认无 Front Matter 或短代码报错。
