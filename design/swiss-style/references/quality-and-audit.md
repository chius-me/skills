# 反模式、质量门禁与评审规范

本文档汇总纸感等宽瑞士网格在生成、改版与评审阶段的反模式清单、五维交付核对表与结构化评审协议，用于在编码前去模板化（De-slop）以及在交付前验证真实体验。

## AI 模板味与反模式避坑表

生成式前端最容易滑向“到处都像 SaaS 着陆页”的默认手癖。除非用户当次需求明确指定，否则严禁引入以下做法：

### 视觉与布局反模式

| 高频模板手癖（严禁） | 为什么破坏纸感瑞士网格 | 本风格的正确做法 |
| --- | --- | --- |
| **SaaS 圆角阴影卡片墙**：把文章列表、归档或个人简介切进一排带 `rgba(0,0,0,.1)` 柔影的大圆角卡片 | 割裂单栏阅读流，制造廉价后台感与“盒中套盒” | 列表保持开放无框，靠 `2.1rem–2.5rem` 垂直留白与字阶自然分组；仅真正可操作的控件使用 `3px–4px` 低圆角描边 |
| **机械堆叠全大写眉题（Eyebrow）**：每个区块 `h2` 上方都顶一行宽字距 `ALL-CAPS` 小标签 | 信息冗余，一眼暴露生成式套路 | 分区直接用 `# 标题` 或清晰短句；仅在 `404 / NOT FOUND` 等确有分类前缀语义处偶用一次 |
| **伪造序号标记（`01 / 02 / 03`）**：给并列链接、标签或非步骤内容强行编号 | 违背“结构即信息”，把装饰伪装成顺序 | 只有真实的时间步骤或操作流程才使用有序列表，并列条目用留白或无序列表 |
| **标题局部换色或斜体挑词**：把一句话里的某个词单独刷成强调色或渐变字 | 破坏等宽字体的整句节奏，流于营销海报腔 | 整句标题保持统一墨色与字重；强调色只给句尾 `.`、前缀 `#` 或真正可点击的链接 |
| **无差别追加箭头与彩色胶囊**：所有按钮末尾都挂 `→`，标签全部做成五颜六色的圆角 Pill | 稀释方向符号与交互色的指路能力 | `↗` 仅标外跳/全集，`←/→` 仅标翻页/返回；标签用朴素的 `#tag` 纯文本链接 |
| **滚动渐显与悬停位移**：每滚一屏段落 `fade-in-up` 上浮、鼠标移上卡片 `translateY(-2px)` 或倾斜发光 | 打断安静阅读，造成视觉跳动与晕动负担 | 页面加载即完整静止可读；悬停只改颜色、下划线或边框底色 |
| **紫色霓虹光晕与大面积渐变洗底**：背景叠模糊色球、玻璃拟态半透明导航栏 | 与纸质克制感正面冲突，降低正文对比度 | 坚持不透明纯平暖纸/蓝灰背景（仅短链接页可选 `.045` 极淡纸纹），页头实底配 `1px` 底线 |

### 文案与微文案反模式

| 文案雷区（严禁） | 典型表现 | 替代写法 |
| --- | --- | --- |
| **AI 虚词与宏大叙事** | “探索未知的数字花园”、“赋能全栈开发之旅”、“无缝衔接的极致阅读体验”、“In today's fast-paced world” | 直接写具体身份、主题或站点用途（如“记录 Homelab、Linux 与日常折腾”） |
| **凭空捏造具体细节** | 编造阅读量、访客评价、`Batch No. 047`、虚构时间线或未配置的社交账号 | 只使用仓库或用户提供的真实信息；缺省项留空或用明确标注的占位说明，绝不留 `[Company Name]` 或 `Lorem ipsum` 残留 |
| **均匀凑字数的排比摘要** | 每条摘要都写成一模一样长度的“不仅……而且……”或尾部强行升华 | 摘要如实提取文章核心问题或结论，长短随内容自然变化 |
| **含糊按钮与前后改口** | 按钮写“提交”，点完提示“操作已完成”；复制按钮无反馈或弹窗打断 | 动词直指结果且前后同词（如 `Copy` → `Copied` → 2 秒恢复 `Copy`） |
| **道歉式报错与空白空状态** | “非常抱歉！服务器开小差了 😢”、搜索无结果时只留一片空白 | 平实交代现状与下一步：如“未找到匹配文章，试试缩短关键词或浏览归档”、“索引加载失败，请刷新重试” |

## 五维质量门禁核对单

在交付新建页面、主题改版或组件重构前，按优先级从高到低逐项核对：

### 1. 无障碍与语义（Critical）

- [ ] **双主题对比度独立达标**：浅色与深色模式下，主文本对比度 ≥ `7:1`（最低 `4.5:1`），次级文本 `--muted` 与链接 `--accent` 在实际承载底色（注意区分 `--bg` 与 `--soft`）上 ≥ `4.5:1`。
- [ ] **瞬时可见焦点环**：纯键盘按 `Tab` 遍历全页，首个焦点落于 Skip link（聚焦时显形且不挤歪布局），所有交互控件拥有清晰的 `2px dashed` 焦点环、无动画延迟、且不被任何固定元素遮挡。
- [ ] **图标上下文语义准确**：紧邻可见文字的装饰图标（如链接行前缀图标、`#`、`.`、`↗`）均加 `aria-hidden="true"`（`<img>` 设 `alt=""`）；无文字独立图标按钮（搜索、主题切换、RSS、社交链接）具备当前语言的 `aria-label`，下拉/折叠与动态提示正确暴露 `aria-expanded`、`aria-current="page"` 或 `aria-live="polite"`。
- [ ] **地标与标题阶梯完整**：每页仅一个 `h1`，正文标题按 `h1 → h2 → h3` 顺序递进不跳级；包含 `<html lang>`、`<main id="main">` 与语义化 `<nav aria-label>`。

### 2. 触控与交互确定性（Critical）

- [ ] **窄屏触控热区**：`<= 760px` 下，导航图标按钮、语言切换器、返回与分页链接的可点击区域 ≥ `44×44px`（或与相邻热区间距 ≥ `8px`），不要求像素级精确点击。
- [ ] **零布局抖动**：鼠标悬停、聚焦、复制状态切换及菜单展开均不改变外围盒子尺寸，不推挤相邻元素。
- [ ] **无悬停独占信息**：桌面端靠悬停显示的元素（如标题锚点 `#`）在键盘 `:focus-visible` 下同样可见，核心导航与阅读功能在触屏上一次点击可达。
- [ ] **动态减弱支持**：`@media (prefers-reduced-motion: reduce)` 下禁用平滑滚动与颜色/透明度过渡。

### 3. 主轴对齐与中英混排（High）

- [ ] **多视口零横向溢出**：在 `1440px`、`768px`、`390px` 与极端窄屏 `320px` 下检查 `documentElement.scrollWidth <= innerWidth`，无任何横向溢出。
- [ ] **单轴贯通与嵌套受控**：索引与阅读页的页头、引言、列表、正文、页脚共享同一左边线；全页无“描边盒内再套描边盒”的多层嵌套。
- [ ] **混排与长串折行稳健**：正文行长控制在拉丁 `< 75ch` / 中文 `32–42` 字；中文标点遵守行首禁则（`line-break: strict`），中英数字间留白规范；超长 URL 与内联代码开启 `overflow-wrap: anywhere`；代码块与宽表格置于独立的 `overflow-x: auto` + `tabindex="0"` 滚动容器内。

### 4. 性能、字体与渐进增强（High）

- [ ] **字体预算受控**：仅 `preload` 首屏必需的主拉丁等宽 `.woff2`（配 `crossorigin` 与 `font-display: swap`）；中文字体采用 `unicode-range` 分片按需加载或直接回退系统字体，避免整包阻塞首屏。
- [ ] **媒体零布局偏移（CLS < 0.1）**：头像与正文图片均声明真实 `width` / `height`（或 `aspect-ratio`）；首屏主图设 `fetchpriority="high"`，屏下图片设 `loading="lazy" decoding="async"`。
- [ ] **文档头与无脚本可用**：`<title>`、不重复的 `<meta name="description">`、`canonical`、多语言 `hreflang`、OpenGraph 及浅/深双 `theme-color` 齐全；禁用 JS 时正文完整可读，纯 JS 控件（如主题切换）自动隐藏或提供 `<noscript>` 退路。

### 5. 极端内容与打印视图（Medium）

- [ ] **压力内容不破版**：用超长中英混排标题（2–3 行）、无标签/无目录短文、多代码块技术长文及 `0` 结果搜索词实测排版稳健性。
- [ ] **打印洁净**：`@media print` 下自动隐藏导航、工具栏、目录、翻页与评论框，正文字色归黑、背景归白，长代码行自动折行不截断。

## 页面评审协议与报告模板

当任务是**评审（Review / Audit）**现有网页或改动时，遵循“先观察真实渲染，后阅读源码定位”的原则：

1. **实测取证优先**：若存在本地服务、构建产物或在线地址，先在浏览器工具中按 `1440`（桌面）、`768`（平板）、`390` / `320`（手机）分别查看浅色与深色模式，实测键盘 `Tab`、菜单展开、检索输入与控制台报错；仅在无法运行页面时声明“仅做静态源码走查”，绝不凭空臆测渲染缺陷。
2. **区分破损与偏好**：只有破坏可用性、无障碍 AA 底线或核心主轴秩序的问题才能标为阻断项（`Blocker` / `High`）。每条问题按「**观察到的现象 → 违背的设计/工程原则 → 具体修复做法**」表述。
3. **保留既有亮点**：明确指出原页面中已经做对的克制细节（如统一的左边线、克制的色板、干净的无脚本回退），防止后续改版误伤。

### 评审输出结构

```markdown
## 页面设计评审 — <页面路径或 URL>
**结论**：<可直接发布 / 修复高优项后发布 / 需结构调整> · **已核验视口**：1440 / 768 / 390 / 320（浅色 + 深色）

### Blocker（破坏可用性、横向溢出或违反无障碍底线，必改）
- [观察到的具体现象与位置] → [违背的原则] → [修复方案]

### High（明显偏离纸感瑞士网格主轴、字阶或双主题对比度，建议发布前修复）
- ...

### Medium（间距节奏、下划线/符号语义、极端内容折行或微文案打磨）
- ...

### Nit（细微优化项，以 `Nit:` 开头）
- Nit: ...

### 值得保留的设计细节
- 列出当前实现中契合本风格且在后续迭代中应保持不变的做法。
```
